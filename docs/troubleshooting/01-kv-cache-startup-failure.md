# 01. KV cache 부족으로 기동 실패

**증상**: bge-m3를 같은 GPU에 올릴 여유를 남기려고 `--gpu-memory-utilization 0.70`으로 기동했더니, 16,384 토큰 요청에 KV cache 2.09 GiB가 필요한데 1.48 GiB만 확보되어 기동에 실패했습니다(ValueError, 최대 길이 4,608).

**원인 분석**: 공식 문서의 메모리 요구량 표는 12B Q4_0을 약 6.7GB로 안내합니다. 이 값은 정적 가중치 근사치이고 KV cache·컨텍스트 메모리는 제외입니다. 실제 기동 로그의 모델 가중치는 8.28 GiB(약 8.9 GB)였습니다. 또 기동 시 멀티모달 프로파일링이 "최대 크기 영상 1개"를 기준으로 임시 메모리를 크게 잡았습니다. 그래서 공식 수치 대신 기동 로그 실측으로 VRAM 예산을 다시 계산했습니다.

**선택지**: ① utilization 상향 ② bge-m3를 CPU로 분리 ③ KV dtype fp8 ④ 멀티모달 입력 제한 ⑤ 최대 컨텍스트 축소(16K → 8K).

**결정**: 에이전트용 긴 컨텍스트가 필요해 ⑤는 제외했습니다. 임베딩은 지연 요구가 낮아 CPU로 충분하다고 보고 ②로 GPU를 Gemma 전용으로 만든 뒤 ①을 0.90으로 올리고, ③으로 같은 공간에 KV를 2배 담았습니다. ④는 video만 껐습니다.

| 항목 | 조치 전 | 조치 후 |
|---|---|---|
| KV cache | 1.48 GiB | 4.77 GiB (74,680 토큰, systemd 기동 로그) |
| 16K 동시 요청 수용 | 0 | 약 4.6 (로그의 4.56x. vLLM 로그 산출치, 실측 아님) |
| 기동 | 실패 | 약 2분 |

**검증**: 이후 KV 형식만 바꿔 벤치마크로 확인했습니다([results.md](../results.md)). **회고**: 문서의 값이 아니라 기동 로그 실측으로 예산을 세우고, 설정 변경은 벤치마크로 효과를 확인해야 한다는 점을 확인했습니다.
