# 한계와 미확인 항목

이 저장소는 단일 개인 랩에서의 서빙 설정과 벤치 기록입니다. 운영 트래픽 경험이나 일반화 가능한 성능 주장이 아닙니다.

## 측정의 한계
- **합성 입력**: 입력 1024·출력 256 랜덤 토큰입니다. 실제 프롬프트 분포, 프리픽스 캐시 적중, 긴 컨텍스트(16K) 부하는 반영하지 않았습니다.
- **라우터 경유**: 모든 측정이 nginx를 거칩니다. 라우터 오버헤드를 분리해 측정하지 않았습니다.
- **반복 횟수**: bf16·fp8 동시 16은 각 1회입니다. fp8 동시 1·4·8은 두 회차(run1·run2)가 있고, bf16 비교에는 run2를 썼습니다. 비교 대상끼리 같은 회차가 아닙니다(동시 16만 같은 run3).
- **지연 변동**: TTFT는 같은 조건에서도 회차 간 차이가 큽니다(동시 4 평균 547 vs 394ms). 처리량 차이는 최대 약 3%였습니다(동시 8: 384 → 372 tok/s).
- **정확도 미측정**: fp8 KV가 답변 품질에 미치는 영향은 측정하지 않았습니다. vLLM도 스케일링 계수가 없으면 정확도가 약간 떨어질 수 있다고 경고합니다.
- **단일 GPU**: 다중 GPU, K8s GPU 스케줄링, Triton/TensorRT/SGLang 경험은 이 저장소에 없습니다.

## 문서 간 불일치·미확인
- 표의 수치는 `bench/summary.sh`와 같은 방식(소수점 이하 버림)으로 출력한 값입니다. 반올림한 값과 최대 1 정도 차이가 날 수 있습니다.
- GPU 사용률·전력·온도는 `gpu_log.sh`와 같은 방식의 CSV로 확인했지만 CSV 원본은 이 저장소에 올리지 않았습니다.
- `run_bench.sh`는 셸에서 쓰던 반복문을 정리한 파일입니다. 깨끗한 환경에서의 재실행은 확인하지 않았습니다.

## 공개하지 않은 것
라우터의 실제 주소·도메인·접근 대역, API 키, 모니터링 계정은 포함하지 않았습니다. 예시 파일은 플레이스홀더입니다.
